# Leerlast-Messung (nicht die Baseline)

**Erhoben:** 2026-08-14, frische Sitzung, trivialer Prompt ("test"), dann `/context`.
**Was das ist:** die Grundlast einer Sitzung *ohne* Arbeitslast.
**Was das nicht ist:** die Baseline nach AP-0.1/AP-0.3 — dafür fehlt der Lauf der Referenzaufgabe.

| Posten | Token | Anteil am 1M-Fenster |
|---|---:|---:|
| System tools | 19.400 | 1,9 % |
| Messages | 5.100 | 0,5 % |
| System prompt | 3.800 | 0,4 % |
| Compact buffer | 3.000 | 0,3 % |
| Skills (15) | 2.100 | 0,2 % |
| **MCP-Werkzeuge (73)** | **0** | — |
| **Summe** | **30.500** | **3 %** |

Umgebung: Opus 5 (1M), Dispatcher in `shadow` (No-op), env-Deckel der Phase 1 aktiv,
`ENABLE_TOOL_SEARCH=true` aus `~/.bashrc:163`.

## Befund: Tool Search trägt

73 MCP-Werkzeugdefinitionen kosten **null Token**, weil sie erst bei Bedarf geladen werden.
Der Korpus schätzte für globale Memory-MCPs "44–54 Tool-Defs ≈ 4,4–8,6k Token je Session"
(FINALIZE B.5) und führte das als Grund, sie nicht als Default zu setzen. Auf dieser
Installation ist der Posten durch Tool Search bereits neutralisiert — gemessen, nicht geschätzt.

Das stützt die Zweitrunden-Empfehlung der Meta-Validierung (§9: `true` ist tokenminimal,
`unset` = `auto` = Schwellenmodus) gegen AP-1.6 des Plans ("nicht setzen").

## Der größte Posten ist nicht angreifbar

**System tools mit 19,4k** sind zwei Drittel der Leerlast — und es sind die eingebauten
Werkzeuge, nicht MCP. Weder der Dispatcher noch einer der optionalen Hooks kann daran etwas
ändern; sie wirken auf Bash-Ausgaben, Read-Ergebnisse und Prefix, nicht auf Werkzeugschemata.
Für Phase 6 heißt das: der messbare Effekt entsteht ausschließlich in der Kategorie
`Messages`, die hier bei 5,1k liegt. Alles andere ist konstante Grundlast in beiden Armen.

## Was für die Baseline noch fehlt

Frische Sitzung in `lauf-baseline/`, Aufgabentext aus `../BASELINE-REFERENZAUFGABE.md` §2
wörtlich einfügen, durchlaufen lassen, **dann** `/context`. Erst diese Zahl ist die Referenz,
gegen die Phase 6 misst — sie enthält die Bash- und Read-Ausgaben, auf die der Dispatcher wirkt.
